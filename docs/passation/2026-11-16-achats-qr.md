# 16 nov. 2026 — lot `achats-qr` : le QR bien placé, les jours justes, la photo de l'achat

Branche `claude/achats-qr`. Captures iPhone de Julien (Achats → À retirer) : « le QR code doit être bien mieux
placé » ; ajout : « je veux qu'il y ait la photo de l'annonce pour le colis que j'ai retiré / à retirer ».

## Ce qui était faux (constaté sur ses captures et dans le code)

1. **Le QR caché** : une icône grise de 26 px sous le code (`.vrm-rpf-qr-mini`), à côté d'un rond « scanner »
   (`va-rond-code`, icône `scan`) qui, lui, ouvrait le CODE en grand — deux icônes ambiguës, le QR perdant.
2. **« encore 3 j » sur la ligne, « encore 4 j » dans la feuille** pour le même colis : la ligne compte des jours
   civils (`delaiRetrait`), la feuille faisait `Math.ceil((limite 23:59:59 − maintenant) / 24 h)` — un jour de plus
   dès l'après-midi.
3. **« Vinted Go · n° 1… »** : le n° coupé, impossible à lire ou copier.
4. **L'onglet du bas « Annonces » surligné sur Achats** : corrigé par la PR #1201 (`barre-achats`), pas refait ici ;
   le banc `achats-qr` le contrôle (Q6) — rouge tant que #1201 n'est pas sur `main`.
5. **Des colis Mondial Relay sans photo ni titre.**

## La mesure (lecture seule, sa base, projections scalaires ; rien recopié dans le dépôt)

- `vrm_colis_retirer` publié : **7 colis à retirer, 1 avec son article (photo + titre), 6 sans** (5 Mondial
  Relay, 1 Chronopost).
- Forme des n° : Mondial Relay = **8 chiffres** dans l'e-mail (82 « disponible ») ET dans le suivi Vinted relevé
  par l'extension (`harvest_{uid}_suivi_{tx}`, 20 lignes `MONDIAL`, 8 chiffres). Même normalisation
  (`normaliserSuivi`) des deux côtés : **aucun défaut de normalisation**.
- E-mails Mondial Relay « disponible » depuis le 1er nov. : **58 n° distincts, 22 reliés** par le suivi Vinted ;
  les 36 autres n'ont **aucune identité** ailleurs : pas dans les 46 lignes de suivi Vinted, pas dans les
  transactions (aucun n° d'expédition, champs `shipment` = id/status seulement), pas dans les 1 379 conversations,
  pas par le code de retrait (0 code commun avec `panel_colis_relais`), pas dans les lignes `transp_*` (pas de tx).
- Cause : le suivi de ces achats n'a pas encore été relu par l'extension (`capterSuivisAchats`, 6/h, compte connecté
  seulement ; listes d'achats de deux comptes au 11 nov., dernière ligne de suivi le 13 nov.). Sur les achats
  « déposé en point relais » depuis le 25 oct. : 11 sur 13 ont leur suivi ; « expédié » : 6 sur 28.

**Donc** : rien à « corriger » dans le rapprochement (le relier par ressemblance est interdit, §5). Le colis sans
identité garde son logo et dit **« Achat pas encore relié · Relier »** ; SON clic choisit l'achat et le n° est
mémorisé comme identité de cet achat.

## Ce qui est fait

- **« Afficher le QR »** (src/CarteRelais.jsx) : un vrai bouton (icône QR + texte, 44 px) dans la rangée de
  « J'ai retiré », seulement quand un QR existe pour CE colis (`qrDe`, par identité). Achats → À retirer au
  téléphone : la ligne d'un colis AVEC QR passe sur deux étages (le colis entier, puis [Afficher le QR] [J'ai
  retiré]) ; ailleurs (Colis, ≤ 480 px) le bouton dit « QR » pour garder une seule forme de ligne, son nom entier
  en `aria-label`. Toucher le **code** ouvre aussi le QR (sinon le code en grand). Le rond « en grand » n'existe
  plus qu'en l'absence de QR, avec une icône « agrandir » (plus l'icône scanner). L'icône grise est retirée.
- **Une seule règle de jours** : `joursRestantsRetrait(jour)` (src/delaiRetrait.js, jours civils de **Paris**,
  `jourParis`), lue par la ligne (`delaiRetrait`) ET la feuille ; la ligne passe en plus SON délai affiché à la
  feuille (`openQrView(t, { delai })`) — la feuille redit exactement « encore N j » (+ « · estimée » si c'est le cas).
- **Le n° de suivi copiable** : toucher le n° le copie en entier (« n° … · copié »), sans ouvrir la fiche ; le n°
  complet est dans son `title`/`aria-label`.
- **La feuille du QR** : toucher le QR l'agrandit (plein écran quand le navigateur l'accepte, sinon toute la
  largeur) ; l'écran reste allumé (Wake Lock existant `GardeEcranAllume`, aucune permission bloquante).
- **« Achat pas encore relié · Relier »** (src/relierColis.js, pur) : `achatDuSuivi(numSuivi, achats, index)` —
  la fonction UNIQUE n° → achat (par identité, celle que le lot `scan-colis-achat` doit réutiliser) ;
  `achatsARelier` (achats en attente sans n° de suivi, « au point relais » d'abord ; pas lus ⇒ null) ;
  `ecritureRelierColis` (la ligne `colis_suivi_{transporteur}_{n°}` avec tx/uid — la même que « Relier à un
  achat » des n° ajoutés à la main, donc « Délier » existe déjà dans « N° de suivi ajoutés »). Après le clic,
  `achatDuColis` relie le colis partout (ligne, feuille, Ma journée, widget).
- Textes par `tr()` (5 langues, `achats.qr.*`, `achats.suivi.*`, `achats.relier.*`) ; ligne « Quoi de neuf ».
