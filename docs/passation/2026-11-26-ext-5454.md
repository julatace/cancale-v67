## Conflits tranchés qui comptent

1. **Favoris, relance sans le même texte (5.441) × favoris réparés (5.453.2)** : gardé les deux.
   `noterTexteEnvoyeFavori` reste noté AVANT l'envoi, avec la frappe « humaine » de la 5.453 ; il est
   aussi noté avant l'offre faite dans la fenêtre d'offre (5.453.2), puisque le texte peut partir
   avec l'offre. La version NEUTRE de la 5.450 (sans le pseudo) respecte aussi « jamais deux fois le
   même texte » (`deja`), dans `background.js` et sa copie `src/favorisPerso.js` (identiques,
   `audit-favoris-perso` P1).
2. **Cloche (5.441 « Voir tout » bouton) × 5.440.2 (lignes comptées)** : le bouton est touché
   d'abord ; sinon la réponse de la 5.440.2 (avec le nombre de lignes). `__vrmFormulaireV` = 10.
3. **Achats au panneau : Vestiaire (5.444) × Leboncoin (5.445)** : une seule variable `achats` ; les
   achats Leboncoin LUS par la 5.445 servent aussi l'onglet « Achats » de la 5.444 (qui disait
   « Leboncoin : pas encore lus ») ; lecture ratée ⇒ `null`, « pas su ». Le message vide Leboncoin
   garde le compte « sans compte » de main.
4. **Republication Vinted : 5.447 (REPUB) × 5.448 (adaptatif)** — les deux lots avaient refait la
   même chose autrement. **Gardée : la 5.447** (déjà fusionnée, capacité `repubreperage`, plus
   stricte : `unique` pour les gestes irréversibles). Les entrées Vinted de la 5.448 (`publier`,
   `supprimerConfirmer`…) sont écartées ; ses appelants (`TABLE_N` de vrm-formulaire.js) prennent les
   noms de REPUB (`ajouter`, `supprimerConfirmation`) ; `TABLE_VERS_MANQUE` connaît les deux noms.
   Gardé de la 5.448 : les tables Leboncoin / Vestiaire / eBay, `souple`, `siteIci`. Deux
   déclarations doublées renommées (`champ` objet ⇒ `champO`, `libelle` ⇒ `libelleA`).
   `__vrmTrouverV` = 4. Banc `ext-adaptatif` accepte le nom de la 5.447 pour la confirmation.
5. **Relais Leboncoin** : la ligne de version cachait le rappel `lastError` de la 5.446 (`audit-ext-
   anciens-lots` R5 l'a vu) — remis.
6. **Liens Leboncoin LUS : photo d'origine (5.446) × N° écrit (5.451)** : UNE fonction
   `liensLbcLus()` = ses liens (posés, défaits), puis le N° écrit, puis la photo d'origine — chacune
   seulement là où rien n'est décidé. Le N° écrit passe devant la photo (c'est SA déclaration) ;
   « Délier » traite le N° écrit puis la photo. Imports doublés retirés (Ebay, Comptabilité,
   Annonces), `liensLbcPoses` déclarée une fois.
7. **CLAUDE.md** : les lignes §9 des lots ne sont PAS recollées (une seule ligne 5.454.0) — elles
