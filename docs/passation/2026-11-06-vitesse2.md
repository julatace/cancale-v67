## Ce qui a changé (src/ seulement)

1. **Dressings** — `SEL_MOISSON` (= la projection de `SEL_COMMANDES`) + `ligneCommandes`
   pour rebâtir `row.data`. `lireDressings(lire, { uids, exclure })` : comptes donnés ⇒
   `id=in.(…)` ; **réponse vide ⇒ relue par motif** (§4.1) ; « pas su » ⇒ `null` ;
   `exclure` ⇒ `id=like.…&id=not.in.(…)`.
   - recherche (`gsData`) : les comptes cherchés (`comptesRecherche`), filtrés ensuite comme avant ;
   - « Tout sur le N° » (`numData`) : **tous les comptes, exprès** (vues, favoris, date de
     mise en ligne d'une paire vendue par un ancien compte), projeté ;
   - Leboncoin : sans les comptes que l'écran écarte de toute façon (`offAcc` : masqués,
     supprimés). Les comptes non liés restent : la file doit être celle de l'extension
     (`buildLbcData` lit tous les comptes, §11), et « vendue sur Vinted → à retirer » a
     besoin de l'état de chaque annonce ;
   - « Le prix qui marche » : comptes liés (`uidsLies(vintedAccounts)`, sinon
     `vrm_comptes_lies`, sinon tous) — seules leurs annonces sont « en ligne » à l'écran Annonces ;
   - `fetchHarvest` (dressing, boîte de réception, par compte) : `select=${SEL_MOISSON}`.
   - `lireExtrasRepartition` (déjà projetée `items`, tous les comptes pour relier les
     ventes d'anciens comptes) : pas touchée.
2. **Achats des comptes liés** — `lireAchatsLies(uids)` (mêmes règles : `id=in.`, vide ⇒
   motif, pas su ⇒ `null`). Registre des achats et export : la liste `vinted_accounts`
   lue d'abord (ils la lisaient déjà), puis leurs seules lignes — « un compte retiré
   n'entre dans aucun total » (les recettes d'à côté sont déjà celles des comptes liés).
   La cloche « où ranger » : **d'abord les achats que le démarrage vient de lire**
   (`achatsDejaLus` : `cachedRow('o:uid')`, 60 s ; elle part 4 s après le nuage), sinon
   `lireAchatsLies(vrm_comptes_lies)`. « Tout sur le N° » et « Le prix qui marche »
   gardent les ventes de tous les comptes (passation précédente).
3. **Premier chargement** (`npx vite build` + analyse des morceaux par module). Le
   morceau `App` : **3 832 Ko / 1 194 Ko compressés** ; App.jsx en fait l'essentiel
   (~4,6 Mo de source) — le découper est un chantier à part, pas fait. Les grosses
   bibliothèques (three, maplibre, jsQR, pdf-lib) étaient déjà à la demande. Partent
   désormais dans des morceaux chargés quand leur écran les rend (`aLaDemande` =
   `React.lazy` + `Suspense`, squelette `SqueletteChargement` en ligne ou pastille
   « Ouverture… » pour une feuille) : Favoris, factures Pro (+ `relireFactures` importé
   au clic), outils d'Achats, écrans eBay (`ebayGestion.jsx`), recherche eBay, fiche
   d'une paire, « Publier ailleurs », « Changer le prix », emballage, scanner, DAC7,
   offres Vestiaire, E-mails des réglages (`ReceptionEmails`, `JournalEmails`), le QR de
   la double vérification (`qrMfa` + `qrcode-generator`, importés à l'activation).
   - Ce dont l'app a besoin sans ces écrans sort tel quel dans son fichier :
     `repereAdmis` → `src/repereEbay.js`, `ResponsiveChatPortal` → `src/ChatPortal.jsx`
     (ré-exportés : leurs lecteurs ne changent pas), `appelerEbay` lu de `ebayRequetes.js`.
   - **Leurs feuilles de style restent importées dans App.jsx, à la place de l'ancien
     import** : le CSS du morceau `App` est **octet pour octet le même** (même empreinte
     `App-CM2cYfGZ.css` avant/après), aucun CSS de morceau à la demande.
   - Écrans montés (`tab===`) : 25 distincts / 38 avant et après ; chaque composant
     déplacé est rendu au même nombre d'endroits (§4.11).
