## 1. « Parfois l'extension se ferme toute seule sur Vinted »

Reproduit au banc (`scripts/bancs/panneau-persistant.cjs`, rouge sur la 5.410.1 : 39 ❌ sur 49) ; quatre causes :

1. **La page retire l'hôte** `#vrm-badge` (Next.js qui refait `<html>` à une navigation ou à une hydratation
   ratée) : rien ne le remettait, la carte disparaissait jusqu'au rechargement. ⇒ `replacerHote()` : l'observateur
   de mutations et un contrôle chaque seconde le remettent aussitôt (panneau, page, défilement gardés). Une copie
   orpheline (extension rechargée) se retire seule ; une seconde injection attend que la première parte.
2. **Une navigation pleine** (lien, retour) recharge le script : l'état « ouvert » vivait en mémoire ⇒ fermé,
   page d'accueil. ⇒ L'état (ouvert, page, sélections articles ET ventes, fiche, conversation, défilement de
   `.corps6`) est rangé PAR ONGLET par le fond : message `panneauEtat` (`lire` / `poser` / `fermer`),
   `chrome.storage.session` (survit au service worker tué, §4.9 ; repli `storage.local` sur Orion), 12 h au plus,
   normalisé. Au chargement, le panneau se rouvre dans le même état. Jamais dans la page (`sessionStorage` du site).
3. **Le survol** du logo ouvrait le GRAND panneau (plein écran) et la sortie de la souris (vers la barre
   d'onglets) le refermait 180 ms après. ⇒ Le survol n'ouvre plus le grand panneau (un clic l'ouvre) ; `pointerleave`
   ne le ferme jamais.
4. **Un toucher sur le voile** autour du panneau (ou sur une page du site) le fermait. ⇒ Plus jamais : seuls son ×
   et Échap (hors d'un champ ou d'une fenêtre du site) le ferment, et l'état est alors oublié.

Le service worker muet (port fermé) ne ferme rien (déjà vrai) ; le rond VRM est caché sous le grand panneau (il
couvrait le coin, le × suffit).

## 2. « Quand j'ai fait une vente, on doit pouvoir imprimer le bordereau, avoir le livreur »

- `carteListes` (ventes) : n° de suivi et date limite LUS dans l'e-mail du bordereau de CETTE vente (`email_bord_*`,
  par n° de transaction, du compte de l'onglet quand l'e-mail le dit ; projections scalaires) ; « bordereau prêt »
  aussi quand l'e-mail porte le PDF. Transporteur : la règle d'avant (`email_track_*`), avec SON logo.
- `bordereauCarte` (fond, LECTURE SEULE, aucune requête Vinted, rien acheté — eBay non concerné, §2.8) : par n° de
  transaction et compte de l'onglet, le PDF capté `harvest_{compte}_label_{tx}`, sinon l'e-mail de CE compte (version
  tamponnée du N° d'abord) ; une page HTML n'est pas un PDF ⇒ `manque` ; base muette ⇒ `passu` ; 10 au plus ;
  onglet Vinted seulement.
- Panneau : Commandes — colonnes Transporteur (logo + nom + n° de suivi), Date limite, Bordereau (« Imprimer » /
  « Pas encore de bordereau » avec la raison en titre / —), case sur les ventes prêtes, « Imprimer le bordereau » /
  « Imprimer les N bordereaux » en haut (la sélection, sinon toutes les prêtes) ; fiche d'une vente idem ; Accueil
  « Capté depuis ta dernière visite » : une vente captée dit livreur, suivi, date limite et s'imprime. Un seul PDF ⇒
  un onglet ouvert DANS le geste puis rempli (sinon téléchargé) ; plusieurs ⇒ un fichier chacun
  (`bordereau-{N°}.pdf`). Leboncoin / Vestiaire : pas de bouton (leur bordereau reste sur le site).
